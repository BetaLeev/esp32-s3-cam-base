## 六、官方优先原则

### 6.1 官方优先
**规则文件**：[official-first.md](.trae/rules/official-first.md)

核心原则：遇到任何技术问题，首先查阅官方文档，找不到方案时必须请示，绝不自己手写

关键规则：
- 代码来源优先级：官方文档 > 官方示例 > 官方库 > 成熟开源库
- 禁止自写协议实现、外设驱动、文件系统操作
- 遇到不确定情况必须请示后再决定

### 6.2 防止复制粘贴开发模式
**规则文件**：[anti-copy-paste.md](.trae/rules/anti-copy-paste.md)

核心原则：复制粘贴 = 重构信号

关键规则：
- 工具函数必须抽象到 utils/ 目录
- 同类代码必须提取公共函数
- 复制前必须检查是否已有现成实现

### 6.3 安全编程规则
**规则文件**：[security-rules.md](.trae/rules/security-rules.md)

核心原则：永远不要信任用户输入

关键规则：
- 所有用户输入必须验证和清理
- 禁止栈上分配大于512字节的数组
- 互斥锁必须使用静态初始化或临界区保护
- 路径操作必须防止遍历攻击

## 一、核心规则

### 1.1 内存管理规则
"请使用 ESP-IDF 标准 POSIX VFS 接口（fopen/fread）。注意：由于 FreeRTOS Task 栈空间有限（4KB），禁止在函数内分配大于 512 字节的局部数组，大缓冲区必须使用 malloc 在 Heap 上分配！"

**运行环境为 FreeRTOS，Task 栈空间只有 [X] KB，严禁在函数内分配大于 512 字节的局部数组，所有大缓冲区必须在 Heap 上分配并检查 NULL。**

区分 POSIX VFS 接口与底层驱动 API，不要混用。

所有硬件 I/O 和文件操作需具备严格的错误处理和超时机制，禁止产生阻塞无限等待。

### 1.2 统一响应格式
所有 Web API 必须使用 `web_module.h` 提供的统一响应函数：

```c
// 响应格式
{
    "status": "success" | "error" | "warning",
    "code": 200,
    "message": "描述信息",
    "data": {...} | null
}

// 使用示例
esp_err_t my_handler(httpd_req_t *req) {
    cJSON *data = cJSON_CreateObject();
    cJSON_AddStringToObject(data, "key", "value");

    return send_success(req, data, "操作成功");
    // 或返回错误
    // return send_error(req, "错误信息", HTTP_NOT_FOUND);
    // return send_bad_request(req, "参数错误");
}
```

## 二、代码规范

### 2.1 头文件包含规范

**标准C库头文件（按功能分组）**

| 功能 | 必需头文件 |
|------|-----------|
| `struct tm`, `mktime()`, `time_t` | `#include <sys/time.h>`, `#include <time.h>` |
| `malloc()`, `free()`, `calloc()` | `#include <stdlib.h>` |
| `strcpy()`, `strlen()`, `strcmp()`, `memcpy()` | `#include <string.h>` |
| `FILE *`, `fopen()`, `fread()`, `fwrite()`, `fprintf()` | `#include <stdio.h>` |
| `printf()`, `snprintf()`, `sscanf()` | `#include <stdio.h>` |

**ESP-IDF 头文件**

| 功能 | 必需头文件 |
|------|-----------|
| `esp_err_t`, `ESP_OK`, `ESP_FAIL`, `ESP_ERR_*` | `#include "esp_err.h"` |
| `ESP_LOGI()`, `ESP_LOGE()`, `ESP_LOGW()`, `ESP_LOGD()` | `#include "esp_log.h"` |
| `xSemaphoreTake()`, `vTaskDelay()`, `xTaskCreate()` | `#include "freertos/FreeRTOS.h"`, `#include "freertos/task.h"` |
| `vSemaphoreCreateMutex()`, `SemaphoreHandle_t` | `#include "freertos/semphr.h"` |
| `gpio_num_t`, `gpio_set_direction()` | `#include "driver/gpio.h"` |
| `i2c_master_bus_handle_t` | `#include "driver/i2c_master.h"` |
| `cJSON_CreateObject()`, `cJSON_AddStringToObject()` | `#include "cJSON.h"` |

**项目内部头文件**

```c
// 优先使用相对路径
#include "../web_module.h"        // 上层目录的模块
#include "sdcard.h"              // 同级目录的模块
#include "../sensors/sensors.h"   // 指定路径
```

### 2.2 常见编译错误诊断

| 错误信息 | 原因 | 解决方案 |
|---------|------|---------|
| `storage size of 'tm_time' isn't known` | 缺少 time.h | 添加 `#include <time.h>` |
| `'struct tm' has no member named 'tm_sec'` | 缺少 time.h | 添加 `#include <time.h>` |
| `implicit declaration of function 'malloc'` | 缺少 stdlib.h | 添加 `#include <stdlib.h>` |
| `implicit declaration of function 'strlen'` | 缺少 string.h | 添加 `#include <string.h>` |
| `implicit declaration of function 'ESP_LOGI'` | 缺少 esp_log.h | 添加 `#include "esp_log.h"` |
| `undefined reference to 'cJSON_*'` | 缺少 cJSON.h 或未链接 | 添加 `#include "cJSON.h"` |

### 2.3 API 设计规范 (RESTFUL)

**HTTP 方法对应操作**

| 方法 | 操作 | 示例 |
|------|------|------|
| GET | 查询/读取 | `GET /api/sdcard/files?path=xxx` |
| POST | 创建/上传/删除 | `POST /api/sdcard/mkdir` |

**API 命名规范**

```

GET    /api/{模块}/data      - 获取数据
POST   /api/{模块}/create    - 创建资源
POST   /api/{模块}/update    - 更新资源
POST   /api/{模块}/delete    - 删除资源
POST   /api/{模块}/upload    - 上传文件
```

**请求/响应示例**

```c
// GET 请求
GET /api/sdcard/files?path=photos
Response: {"status":"success","code":200,"message":"获取文件列表成功","data":{...}}

// POST 请求 - JSON body
POST /api/sdcard/mkdir
Body: {"path": "new_folder"}
Response: {"status":"success","code":200,"message":"目录创建成功","data":{"path":"new_folder"}}
```

### 2.4 错误处理规范

```c
// 1. 检查 NULL 指针
char *buf = malloc(SIZE);
if (buf == NULL) {
    ESP_LOGE(TAG, "内存分配失败");
    return ESP_ERR_NO_MEM;
}

// 2. 检查 API 返回值
esp_err_t ret = some_function();
if (ret != ESP_OK) {
    ESP_LOGE(TAG, "操作失败: %s", esp_err_to_name(ret));
    return ret;
}

// 3. HTTP 处理器错误响应
if (!sdcard_is_mounted()) {
    return send_error(req, "TF卡未挂载", HTTP_SERVICE_UNAVAILABLE);
}
```

## 四、日志规范

### 4.1 模块化日志配置系统

**必须使用 `hw_log.h` 中的模块化日志宏**，禁止直接使用 `ESP_LOGX()`！

**配置方式**：在 `src/config/hw_log.h` 中设置各模块日志级别

```c
// 日志级别定义
typedef enum {
    LOG_LEVEL_NONE  = 0,    // 禁用日志
    LOG_LEVEL_ERROR = 1,    // 仅错误
    LOG_LEVEL_WARN  = 2,    // 警告 + 错误
    LOG_LEVEL_INFO  = 3,    // 信息 + 警告 + 错误
    LOG_LEVEL_DEBUG = 4,    // 调试 + 信息 + 警告 + 错误
} log_level_t;

// 示例配置 - 修改这里即可控制各模块日志
#define LOG_LEVEL_SDCARD    LOG_LEVEL_INFO   // 启用TF卡日志
#define LOG_LEVEL_SENSORS   LOG_LEVEL_NONE   // 禁用传感器日志（调试时改为INFO）
```

### 4.2 使用方法

**每个模块源文件头部**：
```c
#include "config.h"  // 包含日志配置

static const char *TAG = "MODULE_NAME";
#define LOG_TAG TAG     // 定义模块日志宏
```

**使用模块化日志宏**：
```c
// ✅ 正确：使用模块化日志宏
SDCARD_LOGI(TAG, "TF卡挂载成功");
SENSORS_LOGD(TAG, "传感器数据: %d", value);
ACTUATORS_LOGW(TAG, "执行器响应超时");

// ❌ 错误：直接使用 ESP_LOGX
ESP_LOGI(TAG, "TF卡挂载成功");  // 不支持动态开关
```

### 4.3 支持的模块日志宏

| 模块 | 日志宏前缀 | 配置文件开关 |
|------|----------|-------------|
| TF卡 | `SDCARD_LOGX()` | `LOG_LEVEL_SDCARD` |
| 传感器 | `SENSORS_LOGX()` | `LOG_LEVEL_SENSORS` |
| 执行器 | `ACTUATORS_LOGX()` | `LOG_LEVEL_ACTUATORS` |
| 音频 | `AUDIO_LOGX()` | `LOG_LEVEL_AUDIO` |
| 视频 | `VIDEO_LOGX()` | `LOG_LEVEL_VIDEO` |
| WiFi | `WIFI_LOGX()` | `LOG_LEVEL_WIFI` |
| HTTP服务器 | `HTTP_LOGX()` | `LOG_LEVEL_HTTP` |
| Web模块 | `WEB_LOGX()` | `LOG_LEVEL_WEB` |
| 主模块 | `MAIN_LOGX()` | `LOG_LEVEL_MAIN` |
| DNS | `DNS_LOGX()` | `LOG_LEVEL_DNS` |
| SPIFFS | `SPIFFS_LOGX()` | `LOG_LEVEL_SPIFFS` |

### 4.4 快速开关指南

调试某个模块时：
1. 打开 `src/config/hw_log.h`
2. 找到对应模块的 `LOG_LEVEL_XXX`
3. 设置为 `LOG_LEVEL_INFO` 或 `LOG_LEVEL_DEBUG`

禁用某个模块日志：
1. 找到对应模块的 `LOG_LEVEL_XXX`
2. 设置为 `LOG_LEVEL_NONE`

### 4.5 日志级别选择

| 级别 | 使用场景 |
|------|---------|
| `LOG_LEVEL_NONE` | 生产环境，禁用该模块所有日志 |
| `LOG_LEVEL_ERROR` | 仅显示错误（减少日志量） |
| `LOG_LEVEL_WARN` | 显示警告和错误（推荐生产环境） |
| `LOG_LEVEL_INFO` | 显示所有重要信息（调试时推荐） |
| `LOG_LEVEL_DEBUG` | 显示所有日志（包括详细调试信息） |

### 4.6 开发新模块时

1. 在 `hw_log.h` 中添加新模块的宏定义
2. 在源文件中使用模块化日志宏
3. 默认设置为 `LOG_LEVEL_INFO`，调试时改为 `LOG_LEVEL_DEBUG`
